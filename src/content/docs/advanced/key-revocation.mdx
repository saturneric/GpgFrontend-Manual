Sometimes a key can no longer be trusted. It may be lost, stolen, or just no
longer in use. Then you need a way to tell other people to stop using it.

A **revocation certificate** does this. It is a small file that marks one key
as revoked. A revoked key is no longer valid. Anyone who gets the revoked key,
from you or from a key server, can see that they should not use it any more.

Anyone who holds the certificate can revoke the key with it, so keep the file
safe.

## When to Revoke a Key

- **The key was stolen or copied.** Someone else may have your private key.
- **The key is lost.** You cannot get at your private key any more.
- **You stopped using the key.** For example, you moved to a new key.
- **A rule asks for it.** Your organization may require you to replace keys
  from time to time.

Make the certificate ahead of time, while you still have the private key.
Then you can act quickly when one of these things happens.

<Aside type="caution" title="A revocation only counts once others can see it">

Making or importing a revocation certificate changes the key on your computer
only. Other people still see your key as valid, and may keep using it.

After you revoke a key, publish it to a key server or send the revoked public
key to your contacts.

</Aside>

## Make a Revocation Certificate

You need the private key to do this.

There is a shortcut: right-click the key in the **KeyPair Management** window,
open **Key Operations** and choose **Generate Revocation Certificate...**.
That takes you straight to step 3 below.

<Aside type="note" title="New in v2.2.2">

The **Generate Revocation Certificate...** shortcut was added in v2.2.2.

</Aside>

The longer way goes through the key's own window:

<Steps>

1. Open the key's **Key Details** window and click the **Operations** tab. See
   [View Key Pair Details](/guides/view-keypair-info/) for how to open the
   window.

   ![The Revoke Certificate Operation button on the Operations tab][img-1]

2. Click **Revoke Certificate Operation**, then choose **Generate Revoke
   Certificate** from the menu. The button is only there for a key whose
   private primary key you have.

3. The **Revocation Options** window opens. Pick a reason under **Revocation
   Reason (Code)**. If you like, type more details under **Revocation Reason
   (Text)**. Click **OK**.

   ![The Revocation Options window][img-2]

4. Choose where to save the file. Its name ends in `.rev`.

5. Keep the `.rev` file somewhere safe, such as an offline or encrypted
   drive.

</Steps>

## Revoke a Key With a Certificate

This step cannot be undone. Once the certificate is imported, the key stays
revoked.

<Steps>

1. Open the key's **Key Details** window and click the **Operations** tab.

2. Click **Revoke Certificate Operation**, then choose **Import Revoke
   Certificate**.

3. A window called **Import Key Revocation Certificate** asks if you really
   want to do this. Click **OK**.

4. Pick the `.rev` file you saved earlier and open it.

5. The key is now marked as revoked on this computer.

   ![The Key Details window of a revoked key][img-3]

6. Publish the revoked key to a key server. A revoked key's details window has
   only the **KeyPair** tab, so use the key list instead. Open the **KeyPair
   Management** window and click the **Revoked** category. Then right-click
   the key and choose **Publish Public Key to Key Server**.

   This menu item comes from the key server module. See
   [Key Server Operations](/guides/key-server-operations/).

   You can also publish from the command line:

   ```shell
   gpg --keyserver hkps://keyserver.ubuntu.com --send-keys <YOUR_KEY_ID>
   ```

</Steps>

## Good Habits

- **Prepare early.** Make the revocation certificate and back it up before
  anything goes wrong.
- **Store it safely.** Keep the `.rev` file offline or on an encrypted drive,
  so nobody else can revoke your key.
- **Tell people.** After you publish the revocation, ask your contacts to
  refresh your key.

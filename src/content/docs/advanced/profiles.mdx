A **profile** is one complete GpgFrontend setup: its own keys, its own
settings, and its own saved state. Think of it like a separate user account
inside the program.

You already have one, and it works. If one setup is enough for you, you can
skip this page.

:::note[New in v2.2.2]

Profiles were added in GpgFrontend v2.2.2. Before that, the program had one
setup and one only.

:::

## Why You Might Want a Second One

- **Keep work and personal apart.** Two profiles, two sets of keys, no chance
  of sending something with the wrong one.
- **Carry your setup with you.** Save a profile to a file, take it to another
  computer, and pick up where you left off.
- **Try something out.** Open a
  [temporary profile](/advanced/temporary-profiles/) to test a key or a
  setting. It disappears when you close it.

## The Kinds of Profile

The program shows a short type next to each profile:

- **Default**: the one you get when you install GpgFrontend normally.
- **Portable**: the one a portable copy uses. See
  [Portable Mode](/advanced/portable-mode/).
- **Local**: one you made yourself on this computer.
- **From a package**: a profile you opened straight from a file. It is not
  kept on this computer.
- **Temporary**: a throwaway profile. Everything in it is destroyed when its
  window closes. See [Temporary Profiles](/advanced/temporary-profiles/).

## Where Your Profile Lives

The **Default** profile is stored here:

| System  | Folder                                             |
| ------- | -------------------------------------------------- |
| Windows | `C:\Users\<you>\AppData\Local\BKTUS\GpgFrontend\`  |
| macOS   | `~/Library/Application Support/BKTUS/GpgFrontend/` |
| Linux   | `~/.local/share/BKTUS/GpgFrontend/`                |

Profiles you make yourself live in a `profiles` folder inside that one. You do
not have to go looking for them: **Manage Profiles** has an **Open Folder**
button that takes you straight there.

:::tip[Nightly builds stay out of your way]

Test builds keep their files in a separate folder of their own. Trying a
nightly version never touches the setup your installed version uses.

:::

## The Profiles Menu

Everything to do with profiles sits in the **Profiles** menu in the menu bar:

- **Manage Profiles...**: see every profile on this computer, and open or
  remove one.
- **Open Recent**: jump back to a profile you used recently. A profile that is
  already open in another window shows **(open in another window)** and cannot
  be picked.
- **New Profile...**: start a fresh setup on this computer.
- **New Temporary Profile**: start a throwaway setup in a new window. See
  [Temporary Profiles](/advanced/temporary-profiles/).
- **Open Profile File...**: work inside a profile file without copying it onto
  this computer.
- **Import Profile File...**: copy a profile file onto this computer for good.
- **Export This Profile...**: save the profile you are using now to a file.

You can also see which profile you are in at any time. Look at the bottom
right corner of the window: it shows the profile name, and clicking it opens
**Manage Profiles**.

<Aside type="note" title="Not in the Mac App Store Lite edition">

The Lite edition from the Mac App Store has no **Profiles** menu. Everything on
this page needs the full edition.

</Aside>

## Make a New Profile

<Steps>

1. Open **Profiles** in the menu bar, then choose **New Profile...**.

2. In the **Name** box, type a name, such as `Work`. This name shows in the
   profile list and the status bar. You can change it later.

3. Under **Keys**, click one of the two tiles:

   - **Start with an empty keyring** (marked **Recommended**): the profile
     keeps its own keys, separate from everything else. It starts out with
     none, so you import or make some inside it. Only keys kept like this can
     be saved to a profile file and carried away.
   - **Use the system GnuPG keyring**: the profile uses the keys you already
     have. Handy, but those keys are shared with the rest of your computer, so
     they are not really separate, and they cannot travel inside a profile
     file.

4. Under **Settings**, choose what the new profile starts with. See
   [Pick Which Settings to Copy](#pick-which-settings-to-copy) below.

5. Click **Create Profile**. The program asks whether to open the new profile
   now. Click **Yes** to open it.

</Steps>

Opening a profile always opens a **second window**. The window you were in
stays exactly as it was.

### Pick Which Settings to Copy

The **Settings** card lets the new profile start with the settings of the
window you are in, so you do not have to set everything up again.

- **Start with this window's settings** turns all the groups below it on or
  off at once.
- Each group has its own box, so you can copy some and leave out others:
  - **OpenPGP engine and GnuPG**
  - **rPGP passphrase handling**
  - **Everyday behaviour**
  - **Language and appearance**
  - **Diagnostics**

Point at a group to see exactly which settings it holds.

Some things are never copied, whatever you tick. The dialog says so in one
line: **Never copied: keys, key databases, the workspace folder, key
protection and proxy credentials.**

<Aside type="note" title="Changed in v2.2.3">

The **New Profile** window was redesigned, and it can now copy settings from
the window you start it in.

</Aside>

:::note[One window per profile]

The same profile cannot be open in two windows at once. If you try, the
program tells you it is already open somewhere else. This is on purpose:
two windows writing to one profile would damage it.

:::

## Save a Profile to a File

A profile file has the ending `.gfp`. It holds the whole setup, keys included,
in one file you can copy anywhere.

<Steps>

1. Open the profile you want to save.

2. Choose **Profiles**, then **Export This Profile...**. The **Export Profile**
   window opens.

3. Under **Save to**, click **Choose...** and pick where to put the file. The
   window then shows the file name, the folder and how much free space is
   left there.

4. Under **What goes in**, look at the list. If you also want to take your
   workspace files, tick **My workspace files**. It is off to start with.

5. Under **Protection**, type a passphrase. A passphrase is a password, often
   made of several words. It must be at least 8 characters long. Type it a
   second time to confirm it.

   If you cannot think of a good one, click **Generate**. The program makes a
   strong passphrase and shows it so you can write it down.

6. Click **Export**.

</Steps>

<Aside type="caution" title="The passphrase cannot be recovered">

The file cannot be opened without this passphrase. If you forget it, nobody
can open the file again, including you. Write it down and keep it somewhere
safe.

</Aside>

<Aside type="note" title="Changed in v2.2.3">

A passphrase is now required. You can no longer save a profile file without
one. The file is locked with XChaCha20-Poly1305, using a key made from your
passphrase with Argon2id. These are strong, modern ways to lock data.

</Aside>

If the place you picked may be too small, a warning appears at the bottom of
the window. The file is packed smaller as it is written, so it may still fit.

### What Goes In, and What Does Not

The **What goes in** list shows each part and its size:

- **Settings**
- **Saved state, key groups and categories**
- **This profile's own key**. This is the key that locks the profile's saved
  data. See [Application Secure Key](/advanced/app-secure-key/).
- **Keys stored inside this profile**
- **My workspace files**, only if you ticked it

The list ends with a line that says what never goes in: **Never included:
logs, modules, and keys kept elsewhere.**

"Keys kept elsewhere" is the surprising one. Keys live outside the profile
when the profile uses the system GnuPG keyring, or when a key database is
kept on this computer only. Those keys stay where they are. When the profile
is opened on another computer, the program says such a database **is
unavailable** until you point it at a folder there.

Settings that only make sense on this computer also stay behind. For example,
the place where a custom GnuPG is installed, the workspace folder, and how this
profile's own key is protected.

<Aside type="tip" title="Check before you rely on it">

Look at the **Keys stored inside this profile** line. If its size is zero,
your keys are not travelling.

To send those keys too, use a [KeyPackage](/advanced/key-package/) alongside
the profile file. See also [Key Databases](/advanced/key-database/).

</Aside>

### Files From Older Versions

<Aside type="caution" title="Changed in v2.2.3">

Profile files now use a new format. A file saved by v2.2.3 **cannot be
opened by v2.2.2**. Update GpgFrontend on the other computer first.

Files saved by v2.2.2 still open in v2.2.3.

</Aside>

Two new messages can appear when a file will not open:

- **This Profile File Is Too Large**: the file is bigger than this version can
  open. This only happens with files from older versions, which had to be
  held in memory all at once. The program cannot make a file that large
  itself, so the file was made somewhere else or is damaged. Nothing was
  unpacked.
- **Not Enough Room**: there was not enough free space to unpack the profile.
  The file itself is fine. Free some space and try again.

## Open a Profile File on Another Computer

You have two ways to do this, and they behave differently.

### Copy it onto the computer

<Steps>

1. Choose **Profiles**, then **Import Profile File...**.

2. Pick the `.gfp` file.

3. In **Open a Profile File**, type the file's passphrase and click **Open**.

4. In **Name This Profile**, give the profile a name.

5. **Profile Imported** appears. Click **Open** to open it now, or **Not Now**.

</Steps>

It is now a normal profile on this computer, and the file is not needed any
more.

### Work straight out of the file

Choose **Profiles**, then **Open Profile File...**, and pick the file. Or just
double-click the `.gfp` file in your system's file manager.

A new window starts and asks for the passphrase in **Open a Profile File**.
Type it and click **Open**.

Nothing is added to this computer. When you close the window, the program asks
whether to write your changes back into the same file. This is the one to use
on a computer you do not want to leave anything on.

### Open a Profile File From the File Panel

If you double-click a `.gfp` file in GpgFrontend's own
[File Panel](/guides/file-operations/), the program asks first. A window
called **Open Profile File** shows the file and what its header says about
it, such as who wrote it and when.

These details are marked **From the file's header (unverified)**. Anyone who
had the file could have changed them, so do not rely on them yet.

Then choose:

- **Open**: work in the file itself. Nothing is kept on this computer.
- **Import**: copy it into a profile kept here. The file is not used again.
- **Cancel**: do nothing.

After that, the program asks for the passphrase.

### If the File Was Changed

If someone changed the file after it was saved, the program refuses to use it
and shows **This File Has Been Altered**. Do not trust that file. Get a fresh
copy from its owner.

If the file was made by a newer version of GpgFrontend, the program says so
and does not open it. Update GpgFrontend and try again.

### Save Your Changes Back Into the File

When you close a window that runs from a profile file, **Save Changes?**
appears. It reminds you that the copy you are working in is about to be
deleted. Choose:

- **Save Changes**: write everything back into the file.
- **Discard**: throw away everything you did in this session.
- **Cancel**: go back to the window. The question comes again next time you
  close it.

Sometimes the program has to ask for the passphrase again before it can save.
Then **Protect This Profile File** appears:

1. Type the passphrase in **Passphrase**, and again in **Repeat**.
2. Tick **Show passphrase** if you want to check what you typed. The
   **Strength** bar shows how hard it is to guess.
3. Click **Save**.

Whatever you type here becomes the file's passphrase. A different passphrase
replaces the old one, and the old one will no longer open the file.

:::caution[Do not just close and walk away]

If you choose **Discard**, everything you did in that session is gone. The
copy the program was running from is deleted when the window closes.

:::

### Where the Open File Is Kept

While you work in a profile file (or a
[temporary profile](/advanced/temporary-profiles/)), the program needs a
place to keep the unpacked copy. It picks the safest place this computer
offers:

- **Memory**: nothing is written to the disk in the normal course of things.
- **An encrypted folder**: written to the disk, but only this session can
  read it.
- **An ordinary folder on this disk**: used only when neither of the above is
  possible.

To see which one is in use, point at the profile name in the status bar at
the bottom right of the window. Or open **Help**, then **About**, then the
**Status** tab, and look for **Session Storage:**. If an ordinary folder was
used, that line shows under **Needs Attention**.

## If a Profile Is Already Open

When GpgFrontend starts and finds the profile is held by another window, it
shows **Profile Is Already Open**. It names the profile and what holds it.

- **Quit**: close this window and leave the other one alone. This is the safe
  choice.
- **Force Unlock**: take over the profile anyway.

Only use **Force Unlock** if you are sure no other GpgFrontend window is using
this profile. For example, after the program crashed and left its lock behind.
If another window really is using it, both will write to the profile at once
and damage its saved data.

## Delete a Profile

Choose **Profiles**, then **Manage Profiles...**. Pick the profile and click
**Delete**.

The program asks twice, because there is no undo. Its keys, settings and
saved state are removed from this computer for good. Export it to a file
first if you might want it back.

You cannot delete the profile you are currently using, or one that is open in
another window.

## For Advanced Users

You can pick a profile when starting the program from a terminal:

```bash
# open a profile you made, using its folder name
gpgfrontend --profile a3f19c

# open a profile file
gpgfrontend ~/Documents/work.gfp

# open a new temporary profile
gpgfrontend --temp-profile
```

`--profile` needs the profile's **folder name**, not the name you gave it.
You can see the folder name in **Manage Profiles**.

If you name a profile that does not exist, the program stops and says so. It
does not create one for you.

`--temp-profile` opens an empty temporary profile. You may also see
`--temp-profile-settings` in the list of options. The program uses it by
itself to pass settings to a temporary profile it starts. You do not need to
type it.
